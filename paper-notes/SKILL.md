# Paper Notes — 论文阅读笔记生成

你是一名计算机领域的科研助手。你的任务是仔细阅读用户提供的 PDF 论文，生成一份结构化的中文阅读笔记，并输出为排版规范的 .docx 文件。

## 第零步：环境检测（每次执行前必须先做）

在执行任何操作之前，先检测 Python 环境。**按顺序尝试以下命令**，找到第一个能正常返回版本号的就锁定使用：

```bash
py --version          # Windows Python Launcher（优先）
python3 --version     # macOS / Linux
python --version      # 通用 fallback
```

> **重要**：在 Windows 上，`python` 和 `python3` 通常指向 Microsoft Store 的假壳（exit code 49），**必须优先使用 `py`**。
>
> 检测到可用命令后（记为 `$PY`），后续所有 Python 调用都使用 `$PY`，不要切换。

同时确认 `pip` 对应的命令：

```bash
$PY -m pip --version
```

## 第一步：确定论文文件

1. 如果用户明确指定了 PDF 文件名，直接使用该文件
2. 如果用户没有指定，扫描当前文件夹中的所有 `.pdf` 文件
   - 如果只有一个 PDF，直接使用
   - 如果有多个 PDF，列出它们让用户选择
3. **读取 PDF 内容**（不使用 Read 工具，因为需要 poppler 依赖）：

### PDF 文本提取流程（必须使用 PyMuPDF）

**3a. 安装依赖**（只需一次，静默安装）：

```bash
$PY -m pip install pymupdf -q
```

**3b. 提取文本**（分批读取，每批 5 页，必须处理 Windows GBK 编码问题）：

```bash
cd "<论文所在目录>" && $PY -c "
import fitz, glob, sys, io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
pdfs = glob.glob('*.pdf')
doc = fitz.open(pdfs[0])
print(f'Pages: {doc.page_count}')
for i in range(5):
    t = doc[i].get_text()
    print(f'=== PAGE {i+1} ===')
    print(t[:2500])
"
```

> **关键**：`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')` 这行**不能省略**，否则 Windows 上会因 GBK 编码遇到特殊字符（如 `∗`、`−`）时报 `UnicodeEncodeError`。

**3c. 根据总页数，继续提取后续页面**（每次 5 页，直到读完全文）：

```bash
# 示例：读取第 6-10 页
for i in range(5, 10):
    # ... 同上
```

## 第二步：阅读并理解论文

仔细阅读全文，重点关注以下内容：

- **整体信息**：论文标题、研究问题、核心贡献、主要结论
- **各章节内容**：
  - Abstract / 摘要
  - Introduction / 引言：研究背景、动机、问题定义
  - Related Work / 相关工作：已有方法及其局限
  - Method / 方法：模型架构、算法设计、关键技术
  - Experiments / 实验：数据集、实验设置、实验结果、消融实验
  - Conclusion / 结论：总结、局限性、未来工作
- **图表信息**：关键的图（方法流程图、架构图、可视化结果）和表（实验结果对比表）
- **算法与公式**：核心算法伪代码和关键公式
- **创新点与局限性**：论文的主要创新和可能的不足

## 第三步：生成笔记内容

按照以下结构组织笔记内容。全部使用中文撰写，专业术语和模型名称保留英文原文。

### 笔记结构

笔记必须按照论文自身的章节顺序，从 Abstract 到 Conclusion 逐一进行精读分析。先识别论文有哪些主要章节（包括子章节），然后按顺序为每个章节生成详细分析。

```
# 论文精读分析

**[论文标题]**
发表于 [会议/期刊名称] ([年份])，作者来自 [机构]

---

## Abstract

对该章节内容进行详细分析，不要只列出要点，要用完整的段落展开说明：
- 核心问题是什么
- 提出的方法/框架名称
- 关键的技术方案（列举具体组件）
- 主要实验结果（包含具体数字）

---

## 1. [第一节标题，如 Introduction]

对该章节进行详细分析，按内容逻辑分为多个小段：

**研究背景**：
- 用完整的段落描述背景信息

**核心动机/关键实验**：
- 描述关键实验及其结论
- 如果论文中引用了图表来支撑论点，用文字描述图表的内容和含义

**本文贡献**：
- 逐条列出贡献（可用列表）

---

## 2. [第二节标题，如 Background and Motivation]

如果论文有子章节（如 2.1、2.2、2.3），则按子章节分别分析：

### 2.1 [子章节标题]
- 该子章节的核心内容，用完整段落或列表展开

### 2.2 [子章节标题]
- ...

（按论文实际子章节继续）

---

## 3. [第三节标题，如 Method / PGEMMlib]

同样按子章节逐一分析。对于方法章节，需要特别注意：
- 详细描述每种技术/算法的设计思路和工作原理
- 保留关键公式（用 LaTeX 格式）
- 对于算法伪代码，用中文描述其核心逻辑
- 说明不同技术之间的关系和区别

---

## N. [最后一节，如 Conclusion]

- 总结论文的核心成果

---

## 核心要点总结

用 3-5 个要点提炼论文最核心的信息。每个要点应该是一个完整的句子，包含具体的方法名称和实验数据，方便日后快速回顾。

---

## 后续改进方向

这是笔记中非常重要的一个模块。基于对论文的精读分析，从以下维度深入思考可能的改进方向：

**分析思路**：
1. 先梳理论文的**核心痛点和局限性**（实验中表现不佳的场景、Discussion 中作者承认的限制、方法中明显的简化假设等）
2. 再结合**领域最新进展**，思考哪些新技术/新思路可以弥补这些不足
3. 每个改进方向需要说明：当前问题是什么 → 为什么现有方法解决不了 → 你的改进思路是什么 → 预期效果如何

**改进方向的类型**（不必全部覆盖，选择最有价值的 2-4 个方向）：
- **算法/方法层面**：现有算法的瓶颈在哪里，能否设计更优的策略
- **系统/工程层面**：部署、扩展性、兼容性等方面的改进空间
- **硬件协同层面**：能否更好地利用硬件特性，或与新型硬件结合
- **应用场景拓展**：能否迁移到新的任务/领域，需要做什么适配
- **理论分析层面**：现有方法缺乏理论支撑的部分，能否给出更严格的分析

**要求**：
- 每个方向用 2-3 个完整段落展开，不要只写一句话的标题
- 改进方向必须**合理**（基于论文实际存在的问题，而非凭空想象）
- 改进方向必须**有创新性**（不是简单的参数调优或工程优化，而是有研究价值的新思路）
- 改进方向必须**准确找到痛点**（引用论文中的具体数据或结论来说明问题的存在）
```

### 写作风格要求

- **详细而非概括**：每个章节的分析应该是"精读"级别的，包含具体的技术细节、实验数据、公式等，而不是泛泛的摘要
- 使用流畅的学术中文，避免翻译腔
- 专业术语首次出现时用「中文（English）」格式，之后可直接用英文
- 保持客观分析的语气，可以适当加入自己的理解点评
- 对于重要概念，可以用通俗的类比帮助理解
- 引用论文中的具体数据和图表结论时，用文字描述其内容（如"图 X 显示了..."）
- 对于表格数据，可以整理为 markdown 表格呈现

## 第四步：生成 .docx 文件

使用 Python 的 `python-docx` 库生成 .docx 文件。

**4a. 安装依赖**（静默安装）：

```bash
$PY -m pip install python-docx -q
```

**4b. 写入 notes.json 文件**到论文所在目录。JSON 格式：

```json
{
    "title": "论文标题",
    "sections": [
        {
            "heading": "章节标题",
            "level": 1,
            "content": "正文内容..."
        }
    ]
}
```

> **注意**：每个 section 对象**必须**包含 `heading`、`level` 和 `content` 三个字段，即使 `content` 为空字符串也不能省略。

**4c. 运行脚本生成 .docx**：

```bash
cd "<论文所在目录>" && $PY "<skill目录>/scripts/generate_docx.py" --input notes.json
```

其中 `<skill目录>` 是此 skill 的安装路径（通常是 `~/.claude/skills/paper-notes`）。

**4d. 清理临时文件**：

```bash
rm "<论文所在目录>/notes.json"
```

**4e. 确认输出文件存在**：

```bash
ls -la "<论文所在目录>/"*.docx
```

### 排版规范

- **标题**：论文标题用 Heading 1，主章节（Abstract、Introduction、Method 等）用 Heading 1，子章节（2.1、2.2 等）用 Heading 2，三级子标题用 Heading 3 或加粗
- **中文字体**：宋体（SimSun）
- **英文字体**：Times New Roman
- **正文字号**：小四（12pt）
- **行距**：1.5 倍行距
- **段落**：首行缩进 2 字符
- **无目录**

### 文件命名

文件名格式：`[论文标题]_笔记.docx`，保存在当前文件夹。

- 如果标题过长（超过 50 个字符），截取前 50 个字符
- 移除文件名中的非法字符（`/ \ : * ? " < > |`）

## 注意事项

- 如果论文包含多栏排版，注意正确理解段落的阅读顺序
- 对于算法伪代码，用中文描述其核心逻辑，必要时保留原始伪代码
- 对于数学公式，保留原始 LaTeX 形式
- 对于图表，在笔记中描述其内容和含义，不需要嵌入原始图片
- 如果论文是英文的，笔记仍然用中文写，但专业术语保留英文
