# Deck Blueprints — 组会汇报的 8 段结构

流程固定，页数与深度按论文类型和汇报时长调整。所有页面服务同一句话 thesis。

## 一、8 段结构

```
封面 → 背景 → 科学问题 → 关键洞察 → 方法 → 实验 → 结论 → 批判 → 后续改进
```

| 段 | 目的 | 必须回答 | 常见页数 |
|---|---|---|---|
| 封面 | 定调 | 论文是什么、一句话 thesis | 1 |
| 目录 | 给路线图 | 今天按什么顺序讲 | 1 |
| 背景 | 建立必要性 | 为什么现在必须做 | 2–3 |
| 科学问题 | 收敛痛点 | Q1/Q2 是什么、怎么算解决 | 1 |
| 关键洞察 | 解释方法为何可能 | 论文发现了什么 | 1–2 |
| 方法 | 讲清机制 | 每个组件回答哪个 Q | 4–6 |
| 实验 | 给证据 | 哪张图表证实哪条主张 | 5–6 |
| 结论 | 回答开头 | Q1/Q2 逐条：是/部分是/否 | 1 |
| 批判 | 评价论文 | 强项、局限、可疑点 | 2 |
| 后续改进 | 打开讨论 | 下一步做什么 | 1–2 |

## 二、时长映射

### 25 分钟（默认，22–26 页）

| 段落 | 页数 | 配时 |
|---|---|---|
| 封面 + 目录 | 2 | 1.0 min |
| 背景 | 2–3 | 2.0 min |
| 科学问题 | 1 | 1.0 min |
| 关键洞察 | 2 | 2.0 min |
| 方法 | 5 | 6.5 min |
| 实验 | 6 | 6.5 min |
| 结论 | 1 | 1.5 min |
| 批判 | 2 | 2.5 min |
| 后续改进 | 1 | 1.5 min |
| 附录 | 0–1 | 备用 |

### 15 分钟（14–17 页）

- 背景压到 2 页；科学问题与背景末页合并
- 洞察 1 页，直接接到方法
- 方法 4 页（总览 + 3 个组件，组件可合并）
- 实验 4 页（主结果 + 分场景 + 消融）
- 结论 1 页、批判 1 页（强项半页 + 局限主体）、后续 1 页
- 删掉目录页，封面右下角放 3 行路线

### 10 分钟（10–12 页）

- 封面 1；背景 + 问题 2；洞察 + 方法 3；实验 3；结论 + 批判 2；后续 1
- 每个方法只讲"机制一句话 + 一个数字"
- 批判只留 2 条最关键的局限

## 三、每段的内容要求

### 背景（2–3 页）

漏斗结构，最后一页必须停在"缺口"上：

1. 领域现状：问题为什么重要（一页一个数字/趋势）
2. 现有做法：主流路线及其代价（对比表或两栏）
3. 撞墙点：在目标场景下为什么不够（引出 Q1/Q2）

不要写成文献综述。引用不超过 3 篇，且只引与"缺口"直接相关的。

### 科学问题（1 页）

- Q1 / Q2 各一句问句，配"现状 → 目标 → 判定标准"
- 判定标准要可测量（精度不降、传输降几倍、显存上限）
- 这一页在第 2 页目录里就要出现，后面方法/实验反复回指

### 关键洞察（1–2 页）

- 必须是**可测量的观察**，不是作者的直觉宣言
- 每页一个观察：图 + 精确数字 + 出处 + "所以方法可以……"
- 观察要能直接推出方法的设计选择；推不出就删
- 论文没有 observation 时，不要硬造，合并进方法做"设计动机"页

### 方法（4–6 页）

1. 总览页：一张系统图，标出组件 A/B/C 与数据流
2. 每个组件一页，固定四件事：
   - 机制：一句话 + 一张小图/公式
   - 回答哪个 Q（页脚或 pill 标注）
   - 代价：传输/算力/显存，给数字
   - 边界：什么情况下不成立
3. 最后一页可以是参数/调度/实现细节，但要服务于主张

不要把论文 Method 逐节翻译；只讲"为什么这样设计"和"代价是什么"。

### 实验（5–6 页）

固定顺序：

1. 设置：模型、数据、硬件、基线、公平性（同稀疏率/同 batch）
2. 主结果：一张总表或总图，给出核心倍数
3. 分场景：长/短、精度/吞吐、不同模型
4. 消融：每个组件的增量，标 Δ
5. 扩展性/边界：batch、上下文长度、OOM
6. 读法：一句话告诉听众"这张表最该看哪一列"

每张图表旁边放一个"洞察卡"，写清它证实了哪条主张。

### 结论（1 页）

- 把第 2 页的 Q1/Q2 原样搬回来，逐条给"是 / 部分是 / 否"
- 每条配 1–2 个关键数字
- 3 条 takeaway，不写局限（局限属于批判页）
- 视觉上做成闭环：问题卡片 → 答案勾/半勾

### 批判（2 页）

- 第 1 页：强项。讲**可迁移的设计思想**，不要复述贡献
- 第 2 页：局限。分三类：
  - 证据不足（数据集、基线、规模）
  - 假设过强（batch=1、特定模型族、理想化成本）
  - 未解释的差距（理论 3.81× vs 实测 1.3×）
- 末尾给"如果是我，会先补哪个实验"

### 后续改进（1–2 页）

每条写成三行：

```
问题：论文在 X 场景下失效 / 没解释
思路：把 Y 换成 Z，或引入 W
预期：指标 A 提升，代价是 B
```

最后放 2–3 个组会讨论问题，替代"谢谢"。

## 四、标题公式

标题 = **判断句 + 范围**，不是名词短语。

- 差：`组级摘要`
- 好：`组级摘要把粗筛成本降到 1/g，token 级精度不变`
- 差：`实验结果`
- 好：`长上下文吞吐提升 3.7×，但短上下文仍输给 Fast-dLLM`

## 五、三条贯穿线

在 `_deck_plan.md` 里显式维护：

| 问题 | 方法组件 | 证据 |
|---|---|---|
| Q1: 能否在不降精度的前提下减少 KV 传输？ | C1 组级摘要 + C2 预取 | 主表 + 消融 |
| Q2: 动态 KV 下如何保证一致性？ | C3 选择性修复 | 修复消融 / NIAH |

方法页标注回答哪个 Q，实验页标注验证哪条线；对不上的页就是冗余。

## 六、压缩与扩展规则

- 页数不够：先合并背景，再合并方法组件，最后砍附录；不要砍结论/批判
- 页数富余：优先加"洞察"和"分场景实验"，不要加背景
- 理论论文：洞察段换成"核心引理与直觉"
- 系统论文：洞察段换成"设计空间与权衡"
- 测量论文：背景 1 页，洞察和实验各 +1 页
- 综述/立场论文：方法段改为"分类框架"，批判提前
